## Part C — Doc Update Workflow

### Step-by-step for any change:

```
1. Identify the change type from Part B (B1-B10)
2. Check the priority-ordered doc list for that change type
3. 🔴 CRITICAL items MUST be updated before merge — these are blockers
4. 🟡 MEDIUM items SHOULD be updated — create follow-up if not possible
5. 🟢 LOW items are nice-to-have
6. Run `scripts/sync_version_docs.py` if version numbers changed
7. Run `make doctor` to verify the system is still healthy
8. Check `lsp_diagnostics` on all changed doc files
9. Run doc-consistency gates: `python3 scripts/doc_inventory.py --check` (D1-D4) — must exit 0; if the inventory line counts changed, regenerate `python3 scripts/doc_inventory.py` first
```

### Branch naming convention (from CONTRIBUTING.md):

| Prefix | When |
|--------|------|
| `docs/` | Documentation-only changes |
| `feat/` | Feature + its docs |
| `fix/` | Bug fix + its docs |
| `chore/` | Build/config + its docs |

Every non-docs branch MUST include doc updates per the impact matrix above.

## Doc-Consistency Quality Gates (D1-D4)

Four gates keep the documentation consistent with source truth. Run them after any doc-affecting change (also step 9 of Part C). All four are enforced by `python3 scripts/doc_inventory.py --check` (exit 0 = all pass) and by the `omni-doc-inventory` pre-commit hook; `make doc-inventory-check` is the same check via the Makefile.

### D1 — Inventory freshness (P0)

**Criterion**: `docs/dev/doc-inventory.md` exists with its AUTO-GENERATED header; `python3 scripts/doc_inventory.py` regenerates it and `--check` passes (exit 0).

**Verify**: `python3 scripts/doc_inventory.py --check` → prints `docs/dev/doc-inventory.md: AUTO-GENERATED header present -> ok` and exits 0. Stale or hand-edited inventory (missing header, line counts drifted) fails.

### D2 — Source-truth MCP counts (P0)

**Criterion**: every doc's MCP tool-count claim equals source truth: OPP 9 / OL 21 / ORF 7 = **37** total. Docs must never hardcode counts that differ from the MCP server registries — the `--check` counts are COMPUTED from the MCP source files, never hardcoded.

**Verify**: `python3 scripts/doc_inventory.py --check` → prints `SOURCE: OPP=9 OL=21 ORF=7 total=37` and scans claim-site docs for any mismatch. A doc claiming a different count fails the check.

### D3 — Canonical numbers (P1)

**Criterion**: canonical numbers are test matrix **131 PASS / 64 SKIP / 0 FAIL**, nightly **14**, scenario library **119** = **105 tier-1 / 13 tier-2 / 1 tier-3**. Historical measurements must carry explicit markers (e.g. `(--collect-only; canonical: 14)`).

**Verify**: `python3 scripts/doc_inventory.py --check` → prints `scenarios/: 119 yaml files; tiers={'1': 105, '2': 13, '3': 1}` and verifies the canonical test matrix + nightly-test claims.

### D4 — No stale artifacts (P1)

**Criterion**: no `tests/test_bug_*` files; version sync confirmed by the `omni-version-docs-sync` hook; inventory header present.

**Verify**: `python3 scripts/doc_inventory.py --check` → prints `Stray test_bug_* files in tests/: none -> ok`; the check also delegates version-sync to `scripts/sync_version_docs.py --check` and verifies the inventory header.
